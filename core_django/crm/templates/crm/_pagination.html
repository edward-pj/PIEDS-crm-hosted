{% comment %} Page navigation and the rows-per-page picker, for every list screen. The links use {% templatetag openblock %} querystring {% templatetag closeblock %} (a Django 5.1 builtin) rather than `?{{ request.GET.urlencode }}&page=N`, which is what this used to do. That form re-appended `page` to a query string that already contained one, so clicking Next three times produced `?page=2&page=3&page=4`. It happened to render the right page -- Django reads the last value -- while the URL grew on every click and became useless to share or bookmark. The tag REPLACES a key instead of appending it. Changing the page size resets `page` to the first page on purpose: page 7 of 50 is not page 7 of 300, and landing past the end after switching is how a picker looks broken. Which size is current comes from `page.paginator.per_page` -- the size actually in force -- and never from a value passed alongside it.
